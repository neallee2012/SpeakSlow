# SpeakSlow vs Typeless 人工盲測協議

Typeless 沒有 API，自動對比做不到——用這份協議做公平的人工對比（一個下午）。

## 準備
1. 安裝 Typeless 試用版（Windows），語言設 zh-TW。
2. SpeakSlow 開 Azure 串流 + AI 潤飾。
3. 準備一份純文字檔記錄結果。

## 測試句（10 句，涵蓋十個考科；照唸，含「呃」等贅字要真的唸出來）
1. 呃我想那個約週三下午開會討論一下預算
2. 這個這個方案的的優點是便宜（重複）
3. 會議定在週三，呃不對，是週四早上十點（改口）
4. 要準備的東西有第一簡報第二報價單第三合約（清單）
5. 預算是 47 萬不是 45 萬，王小明負責（保護：數字+人名）
6. 請把這段文字重新潤飾一遍讓它更通順（同音詞風險）
7. 我們用 Azure OpenAI 跟 MCP 做整合測試（中英混用）
8. 就是那個系統它會自動地去做一個備份的動作（調順）
9. deadline 是 Friday 中午，記得先跟客戶 confirm（混用+保護）
10. 一段 60 秒的自由發言（真實工作情境，兩邊唸同稿）

## 執行
- 每句分別用兩個工具各唸一次（同麥克風、同環境），把輸出貼到記錄檔。
- **盲評**：把 20 條輸出去掉來源標籤、隨機排序，隔天（或請同事）逐條打分。

## 評分（每條 1-5 分 × 三維度）
| 維度 | 5 分 | 1 分 |
|------|------|------|
| 正確（聽對+修對） | 詞全對、錯字修對不亂猜 | 關鍵詞錯/腦補 |
| 保意 | 數字/立場/名字一字不差 | 意思被改 |
| 順暢 | 像寫的 | 像逐字稿 |

另記每句「放手→出字」秒數（體感延遲）。

## 判讀
- 兩邊分差 <0.5：能力等價，選隱私/成本/整合性。
- SpeakSlow 落後集中在某考科：回頭調 prompt/字典，跑 `npm run eval` 驗證收斂。
- 落後在「正確」科：是 ASR 層問題（熱詞/修正字典），不是潤飾層。
