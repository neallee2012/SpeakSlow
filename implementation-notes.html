設計決策（spec 模糊處的選擇）

D-A 路徑②本地 sidecar，非 in-app MSAL。 重用你既有 aoai-proxy.py pattern；SpeakSlow 對 Azure 只看到 localhost OpenAI 相容端點。一次躲掉雙 audience / 不可逆 custom subdomain / aad# 包裝 / Electron 原生模組 ABI。
D-B ASR inbound 用 raw audio/wav body，非 multipart。 SpeakSlow↔sidecar 兩端都是我們的，省掉 inbound multipart 解析（Python 3.13 已移除 cgi）。sidecar 只在 對 Azure 那一段組 multipart。
D-C chat 的 deployment 由請求 model 欄位決定（fallback AZURE_CHAT_DEPLOYMENT）。使用者改 SpeakSlow 的 ai_model 設定即可換模型，符合「保留彈性」。
D-D ASR 預設 locales:[]（多語自動）→ 既有 OpenCC 轉繁。 mai-transcribe-1 多語模型清單有 zh-CN 無 zh-TW；多語模式原生處理中英混用（晶晶體）。要強制可 ?locales=zh-TW。
D-E 單一 scope cognitiveservices.azure.com/.default 同時涵蓋 chat + 轉寫（foundryweus2 是單一 AI-Services 資源）。一次登入、一組憑證。
D-F 用 azure-identity + 持久化 AuthenticationRecord，自動續期、重啟免重登。get_token 加鎖避免同時彈兩個瀏覽器。

與原研究的差異（驗證後修正）

偏離原研究：ASR 改用 Speech Fast Transcription + mai-transcribe-1，非 OpenAI /audio/transcriptions。依你提供的 curl。驗證確認 Fast Transcription 用純 Bearer（非 aad# 包裝），仍維持 path② 的「單 token」優勢。
修正：Speech custom subdomain 風險消失。 你的 foundryweus2.cognitiveservices.azure.com 本來就是 custom subdomain → Entra 直接可用，不需再開不可逆設定。
升級：segments 在 Azure 模式可保留。 Fast Transcription 回 phrases[].offsetMilliseconds/durationMilliseconds，sidecar 映成 segments → 停頓斷行/SRT 不必降級。原 spec 假設會降級為純文字。

為什麼不用 Speech SDK 串流（先前驗證的結論，現已轉為 batch）

以下是 workflow 對「Azure Speech 串流 SDK 取代本地串流」的對抗式驗證，結論 PARTIAL；正因這些痛點，最終選 batch Fast Transcription（sidecar）而非 SDK 串流。保留作為決策依據。

  • 控制流相反： renderer 目前是同步 request/response（每 250ms chunk await 一個結果），Azure SpeechRecognizer 是事件式（recognizing/recognized）。要硬接串流得新增 webContents.send 事件推送通道並重接 useStreamingRecording.js。
  • 分段衝突： renderer 自己做 VAD（SILENCE_THRESHOLD=0.01, SILENCE_DURATION=500ms）並逐段重啟 sherpa session；Azure server 端用 Speech_SegmentationSilenceTimeoutMs 自己分段，兩者並存會雙重分段。
  • interim 貼上非小改： 現在 partial 只進 UI overlay（App.jsx:1601），貼上是 final 時 clipboard save→write→Ctrl+V→restore（clipboard.js:262）。「interim 覆蓋貼上」要在前景 app 做 select-all/backspace 取代，侵入且會洗掉使用者文字。
  • SDK + Entra 摩擦： custom-domain Entra 需 SpeechConfig.fromEndpoint（docs 不建議用於串流），且續期要靠 TokenCredential 自動刷新。

結論： 串流固定走本地 sherpa；Azure 模式 batch-only（Fast Transcription REST），整段避開上述四個痛點。
